# AKNexus Framework 包依赖架构设计

## 设计原则

1. **底层包放在底层项目**：核心框架包集中在基础设施层，避免逻辑扩散
2. **最小依赖原则**：每层只引用必要的包
3. **依赖向下传递**：上层通过项目引用自动获得下层能力

---

## Furion 包结构分析

### 核心包
| 包名 | 用途 | 依赖 |
|------|------|------|
| `Furion` | 完整包（含 Swagger） | Swashbuckle.AspNetCore |
| `Furion.Pure` | 纯净包（不含 Swagger） | 无第三方依赖 |

### 扩展包
| 包名 | 用途 | 依赖 |
|------|------|------|
| `Furion.Extras.Authentication.JwtBearer` | JWT 认证扩展 | Microsoft.AspNetCore.Authentication.JwtBearer |
| `Furion.Extras.ObjectMapper.Mapster` | Mapster 对象映射 | Mapster |
| `Furion.Extras.DependencyModel.CodeAnalysis` | 代码分析 | - |

## 各层 csproj 配置

### 1. AKNexus.Framework.Abstractions
```xml
<Project Sdk="Microsoft.NET.Sdk">
  <PropertyGroup>
    <TargetFramework>net8.0</TargetFramework>
  </PropertyGroup>
  <!-- 无包引用，零依赖 -->
</Project>
```

## 包传递关系总结

| 层级 | 直接引用包 | 通过项目引用获得的包 |
|------|-----------|---------------------|
| **Abstractions** | 无 | - |
| **Domain** | 无 | - |
| **Application** | 无 | - |
| **Infrastructure** | Furion 全系列、EF Core、Redis | - |
| **Web** | Asp.Versioning | Furion（通过 Infrastructure） |
| **Hub.Web** | HealthChecks | Furion、EF Core、Redis、Mapster（全栈能力） |

---

## 核心优势

1. **包集中管理**：所有 Furion 包集中在 Infrastructure 层，统一版本管理
2. **依赖清晰**：上层不直接引用框架包，通过项目引用传递
3. **易于升级**：只需在 Infrastructure 层升级框架版本
4. **逻辑不扩散**：技术实现代码集中在基础设施层
